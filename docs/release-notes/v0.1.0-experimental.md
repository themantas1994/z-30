# z-30 v0.1.0-experimental

The first release of z-30: an experimental amateur-radio weak-signal HF digital mode and the
native software that operates it. Nothing was published before this; there is no upgrade path to
describe and no earlier archive to compare against.

## Status — read this first

| | Status |
| :--- | :--- |
| **Protocol validated** | **Yes, against the frozen reference.** The Rust implementation reproduces the reference oracle's golden vectors — CRC-14, the LDPC (216, 77) encoder, the symbol map, the message codec and the GFSK waveform — bit for bit, checked in CI. |
| **Software simulation validated** | **Yes.** The receiver is measured through its production entry point (`decode_slot`) in seeded simulation: AWGN, drift, timing and clock error, busy bands, collisions, fading, false decodes. |
| **Hardware not validated** | **No radio, audio interface or PTT interface has ever been used with z-30.** Not by the authors, not in CI, not once. There is no hardware-validation record in this repository. |
| **On-air not validated** | **No z-30 frame has been decoded over a real radio path.** No other software speaks z-30, so there is nobody to work. |

z-30 is experimental. Passing tests does not make it fit to key a transmitter. This software
drives PTT and generates the audio a radio radiates; a defect does not produce a stack trace, it
produces an out-of-band, misidentified or stuck transmission on your licence. Before you
transmit anything, read [docs/safety.md](../safety.md) and
[wiki/13](../../wiki/13-Operating-Safety-Compliance-&-Security.md), and follow
[docs/hardware-validation.md](../hardware-validation.md) — into a dummy load, with a known-good
receiver watching.

A fresh installation **cannot transmit**: it has no callsign, region, licence class, PTT method,
dial frequency or transmit level, and there are no defaults for any of them. The transmit gate
refuses and lists every reason until you set them yourself.

## What is in the release

Two native programs per platform, built by CI from this tag, with CM108/CM119 GPIO PTT compiled
in:

- **`z30-gui`** — the desktop station: waterfall, decodes, QSO sequencing, the transmit gate, the
  logbook.
- **`z30`** — the command-line station and toolbox: receive-only live station, decode and encode
  recordings, diagnostics, migration from the retired browser/Python version, ADIF, the software
  loopback test, the benchmark suite. **It never transmits.**

| Archive | Platform |
| :--- | :--- |
| `z30-0.1.0-experimental-x86_64-unknown-linux-gnu.tar.gz` | Linux x86-64 (glibc 2.35 or later) |
| `z30-0.1.0-experimental-x86_64-pc-windows-msvc.zip` | Windows 10/11 x86-64 |
| `z30-0.1.0-experimental-aarch64-apple-darwin.tar.gz` | macOS, Apple Silicon |
| `z30-0.1.0-experimental-x86_64-apple-darwin.tar.gz` | macOS, Intel |

Each archive holds the two binaries, `README.md`, `LICENSE`, `INSTALL.md` and `BUILDINFO.txt`
(the binaries' own `--version` output, which names the exact commit); the Linux archive also
carries the `.desktop` entry and the icon. Nothing else — no Python, no Node, no browser bundle.
Verify against `SHA256SUMS`, then check that `./z30 --version` matches `BUILDINFO.txt` and this
tag's commit. Installation: [docs/install.md](../install.md).

The binaries are **not code-signed**. macOS needs right-click → Open (or `xattr -d
com.apple.quarantine z30 z30-gui`) on first launch; Windows SmartScreen warns once.

## The mode

A 63-bit message (two 28-bit callsign fields and a 7-bit extra field) plus a 14-bit CRC — 77
information bits — LDPC (216, 77) encoded and sent as a 24-second, ~50 Hz-wide,
continuous-phase 16-GFSK frame inside a 30-second UTC slot. The receiver acquires blind across
200–2800 Hz and ±1.5 s, demodulates non-coherently, decodes with a belief-propagation cascade
and a corrected ordered-statistics decoder, and runs up to three passes of least-squares
successive interference cancellation. [`SPEC.md`](../../SPEC.md) is the normative protocol text.

The codec **refuses** what protocol v1 cannot carry exactly — non-standard callsigns, grids
outside the 63-square table, reports outside −30…+30 dB — rather than transmitting something
else in its place.

## Measured sensitivity — simulation only

> **vNext `decode_slot`: 50% decode at −23.03 dB [−23.13, −22.89], 90% at −22.06 dB [−22.15,
> −21.80].** AWGN simulation; SNR in a 2500 Hz reference bandwidth (SPEC §10); blind acquisition
> (tone 0 uniform over 210–2740 Hz, DT uniform over ±1.4 s, random carrier phase, random
> payload); success = the decoded 63 payload bits equal the transmitted ones; 200 frames per SNR
> point; suite seed 20260830; Wilson 95% intervals; 0 false decodes in the sweep. Source:
> `research/results/672cef9b3cdb/awgn.json`. Pooled over 2200 frames per point: −23.00 dB
> [−23.04, −22.96]. **Simulation. Not measured on real radio hardware.**

Against FT8 — all of it or none of it:

- About 2 dB deeper than FT8's published −21 dB, itself a simulation figure (Franke, Somerville &
  Taylor, *QEX* 2020) whose conditions are not identical to these. No FT8 decoder was run on the
  same channel.
- Bought with 1.9× the airtime (24.0 s against 12.64 s) and 14 fewer message bits (63 against
  77). **Per message bit, z-30 needs about 1.6 dB more Eb/N0 than FT8** (6.8 dB against 5.1 dB).
- On ITU-R F.1487 high-latitude moderate (10 Hz Doppler) z-30 **does not decode at any SNR**: the
  Doppler spread is wider than the 3.125 Hz tone spacing.
- FT8 does recover collisions; WSJT-X runs three passes with subtraction.

Every figure above is a seeded software simulation through the shipped receiver. How the
measurements are made and how to reproduce them: [docs/benchmarking.md](../benchmarking.md).

## What this release does not do

- It has not been operated with a radio. Rig control (rigctld/Hamlib), serial RTS/DTR PTT, CM108
  GPIO PTT and the audio path are implemented and unit-tested, and **none of them has been
  exercised against real hardware**.
- It has no time source of its own. z-30 reads the operating system clock, never sets it, and
  reports "synchronised" only when the OS does. Keep the machine on UTC with NTP or GPS.
- It reports no per-decode confidence, and `Decode::snr_db` is absent (shown as `--`, and no
  report is sent) when it cannot be estimated. Nothing displayed is a plausible default.
- Nothing else in the world speaks z-30.

## Verifying what you downloaded

```bash
sha256sum -c SHA256SUMS --ignore-missing
./z30 --version          # must name this tag's commit, and match BUILDINFO.txt
./z30 --loopback-test    # software only: no audio device, no PTT, no rig control
./z30 --diagnostics      # configuration, OS clock, audio devices, transmit-gate verdict
```

`--loopback-test` runs a frame from the production transmit synthesis through the production
receive pipeline in memory. It cannot reach a transmitter — the module has no audio output, no
PTT line and no rig control in it at all — and passing it is software evidence, **not** hardware
validation.
